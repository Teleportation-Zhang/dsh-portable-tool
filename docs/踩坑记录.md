# 踩坑记录

这套工具是踩出来的，每一条都对应一次真实的崩溃或数据问题。

## 1. DSH Desktop 的 userData 是硬编码的

`configureAppIdentity()` 里：

```js
app.setName("DSH Desktop");
app.setPath("userData", join(app.getPath("appData"), "dsh-desktop"));
```

**每次启动无条件执行**，`--user-data-dir` 会被覆盖。所以便携化只能靠 junction：

```
%APPDATA%\dsh-desktop  →  U盘\data\dsh-desktop
```

## 2. FAT32 / exFAT 建不了 junction

`New-Item -ItemType Junction` 在 FAT32 上报 `Incorrect function`。U 盘必须 NTFS。

**代价**：NTFS 插 Mac 只读，插电视/车载可能不认。

## 3. DSH 启动时会重写 package.json

`healProfileBundles()` 每次启动都跑：遍历 dependencies，凡"已安装 + 声明了 dsh.bundle.patch + 不在 bundles"的，全部加回 bundles。

**后果**：你勾选不加载的插件，下次启动又被加回来。

**解法**：删对应插件 `package.json` 里的 `dsh.bundle.patch` 键（只删这个键，留 `dsh.bundle = {}`），让 `inspectPackage` 判它不是 bundle。

**坑**：如果 node_modules 里那些插件是 junction，改 package.json 会**穿透到源目录**（.generations），污染原始包 → 目标机 preflight 报 `dsh.bundle.patch must be a file path or a list of file paths`。

## 4. link 安装的插件不在 lockfile 里

本机用 `pnpm.overrides` 的 `link:../.generations/live/...` 装的插件，`pnpm-lock.yaml` 里**没有条目**。

**后果**：如果同步时把 overrides 清空（为了"便携"），目标机 lock-recovery 判定解析不到 → 从 dependencies 裁掉 → bundles 变孤儿 → 插件消失。

**解法**：`.generations` 一起复制到 U 盘，overrides 保留原样（相对路径有效）。

## 5. BOM 会让 DSH 起不来

PowerShell 5.1 的 `Set-Content -Encoding UTF8` 会写 BOM。DSH 用 `JSON.parse` 读 `workspace.json` / `package.json` → `Unexpected token ''` → 4 个必需插件未激活 → 启动失败。

**解法**：

```powershell
[System.IO.File]::WriteAllText($path, $text, (New-Object System.Text.UTF8Encoding($false)))
```

所有 `.ps1` 自己反而要 **UTF-8 BOM**（否则 PowerShell 5.1 按 ANSI 解析中文报语法错误）。

## 6. 控制台卡死 = UI 线程做了 U 盘 I/O

接管期间 `%APPDATA%\dsh-desktop` 是 junction，`Get-DirSize $HostHarness` 实际在扫 U 盘（几千文件、USB 随机读）→ 几十秒 → Windows 判定"未响应"关掉窗口。

**解法**：接管期间用 manifest 记录的 `syncBytes` 显示体积，不碰 U 盘；进程路径按 PID 缓存，避免每 2 秒读 U 盘进程。

## 7. 还原必须在清理之前

`关闭 DSH 并清理` 原顺序：杀进程 → 删 U 盘 cache → 还原。清理卡死时，还原永远不执行 → 主机数据停在 `portable-backup`，主机 DSH 顺着 junction 读了 U 盘数据。

**解法**：顺序改成 杀进程 → **还原** → 清理。改名是瞬时操作，不会卡。

## 8. 崩溃兜底：标记文件

即使还原前进程被杀，`%APPDATA%\dsh-desktop.portable-takeover.json` 记录了备份位置，下次打开控制台自动还原。

## 9. U 盘版不要装插件

`.npmrc` 的 `store-dir` 和 `node_modules\.modules.yaml` 的 `storeDir` 是主电脑路径（`C:\Users\<主电脑用户>\...`），目标机用户不同 → 装/更新插件时 `EPERM: operation not permitted, mkdir`。

**解法**：要装插件回主电脑装好再同步。或者改 store 路径（会触发离线装不了的硬链接重装）。

## 10. 单实例锁

DSH 用 `requestSingleInstanceLock()`，基于 userData。两个实例用同一份数据时，第二个直接退出（表现为"点了没反应"）。
